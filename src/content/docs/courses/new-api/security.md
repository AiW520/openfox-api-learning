> **学完能做什么：** 完成一个可验证的输入边界实验，并识别仍需审计的保护。

## 必要概念

对象级授权（object-level authorization）验证当前身份对具体数据的访问权；限流（rate limiting）约束调用频率，不能替代授权。

| 主题 | 状态 | 证据与限制 |

| 身份与对象授权 | 已发现实现 | tokenRoute 中间件，model 中 id/user_id 查询 |

## 实验：名称边界与跨用户删除

1. 在隔离副本、空数据库创建两个实验用户 A/B；保留初始数据库快照。
2. 找到 AddToken 的名称校验，记录当前边界及长度单位；分别提交空名称、边界长度和超限名称，用中文和 ASCII 各做一组。
3. 同时记录 HTTP 状态、success/message 和数据库行数。超限输入不应写入；空名称是否允许由该版本规则决定，不能自定答案。
4. 在副本把名称上限调小，补对应表驱动测试；通过 Gin httptest 请求处理函数，设置合成身份上下文，使用临时数据库。
5. 由 A 创建令牌，B 删除同一编号；验证 A 的记录仍在。再用 A 删除，查询应消失。
6. 恢复副本中的校验改动和测试库快照。本次未实际运行此 Go 实验；提供的是验证方案。

参考思路：断言业务结果和持久化结果，不能只 assert HTTP 200。若测试直接调用 model，仍需另测路由认证，避免绕过真正入口。

## 日志、部署与维护

用请求编号关联 controller 错误与数据库错误；脱敏后记录原因，不输出密钥。构建由 web 脚本和 Go 编译组成，源码内 workflow 需要按版本再验证发布权限。性能热点关注分页查询、连接池、上游延迟、长连接与重试放大；没有实测不提供吞吐数字。此教程站的部署与原网关服务部署是两件独立的事。
